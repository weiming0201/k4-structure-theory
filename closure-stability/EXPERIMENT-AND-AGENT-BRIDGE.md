# 从闭合个体实验到任务型 Agent：实验与工程映射（初稿）

> 状态：隔离 Candidate；尚未实现、运行、采用或发布。
>
> 唯一数学前提来自同目录的 [MATHEMATICAL-FOUNDATION.md](./MATHEMATICAL-FOUNDATION.md)。
> 本文可以提出领域解释和实验假说，但不能反向改变数学定义。

## 0. 本文要回答什么

本文设计两个相接但分层的实验：

1. 在可复现的二元扰动环境中，检验“闭合后感知、感知后行动、行动提高延续”的哪些部分
   成立；
2. 把相同的消融方法投射到真实任务型 Agent，判断今天的模型 API、harness、Workspace、
   History 和 Tool 分别承担了什么，系统偏科在哪里。

主问题不是“能否模拟生命”，而是：

> 一个系统若要在不确定环境里持续完成任务，哪些稳定职责必须有独立载体，哪些能力可以
> 由高性能计算核心代偿，哪些代偿会制造噪声、脆弱性和不可恢复状态？

## 1. 与既有实验谱系的关系

### 1.1 巴里赛利提供了什么先例

Nils Aall Barricelli 在 1953 年使用 IAS 计算机研究人工数值宇宙中的演化。IAS 档案保存了
其 1953 年的 *Experiments on Bionumeric Evolution Executed by the Computer at Princeton,
NJ*；IAS 的人物说明将其工作概括为用数串表示人工生物群体，并通过突变和遗传交换观察
种群演化。其 1972 年论文说明前八节整理自 1957、1962 和 1963 年的早期结果，而演化与
竞争实验在 IAS 计算机上完成。

来源：

- [IAS Electronic Computer Project records](https://www.ias.edu/sites/default/files/library/page/ECP.html)
- [IAS: Nils A. Barricelli](https://www.ias.edu/scholars/nils-barricelli)
- [Barricelli, Numerical testing of evolution theories](https://doi.org/10.1080/00949657208810008)

本实验与其相似之处是：使用可枚举的数字环境、随机初态、局部变化和长程迭代，让稳定
结构的持续时间由运行结果而非研究者叙事决定。

本实验与其不同之处是：首轮不追求开放式物种、竞争或新颖性，而先固定闭合判据、感知
通道、行动预算和配对反事实，专门测量工程稳定性。若这套最小模型成立，种群、共生、寄生、
繁殖和开放式演化才是后续层。

### 1.2 两个理论校准点

自创生理论把重点放在一个过程网络持续产生并实现自身组织与边界，而不是把繁殖当作生命
成立的必要前件。[Varela, Maturana and Uribe, 1974](https://pubmed.ncbi.nlm.nih.gov/4407425/)

Ashby 则从动态系统、稳定、作为稳定的适应、超稳定系统和 Homeostat 逐层讨论适应性；这
支持我们把“在扰动下留在可生存区域”作为工程指标，而不把增长或复杂化预设为目标。
[Design for a Brain](https://ashby.info/Ashby%20-%20Design%20for%20a%20Brain%20-%20The%20Origin%20of%20Adaptive%20Behavior.pdf)

这些来源提供问题和方法谱系，不证明本文的四分或五阶段。

## 2. 实验 A：二元扰动世界

### 2.1 首轮世界

固定：

```text
世界长度 N
局部系统长度 m
每位每步翻转概率 p
总步数 T
随机种子 seed
每轮行动预算 b
```

世界是长度 `N` 的环形二元数组。首轮只使用独立翻转，不使用插入删除，以免位置身份和
长度变化成为额外变量。每次实验保存完整配置、种子和逐步事件，因此任何曲线都可重放。

### 2.2 个体不是任意括号

研究者预先冻结一个解码器和四个闭合检查。候选区间只有同时通过四项检查才计为闭合：

| 符号 | 首轮实验解释 | 机械检查 |
| --- | --- | --- |
| `q₁` | 结构边界 | 边界标识、内部地址和允许交换规则可由当前编码重建 |
| `q₂` | 运行能力 | 固定解释器能从当前编码启动一步合法内部转移 |
| `q₃` | 稳定内容 | 声明的逻辑载荷能从当前物理编码无歧义解码 |
| `q₄` | 接续历史 | 当前状态能绑定上一步身份、事件和恢复基线 |

这四个名字是实验解释，不是数学定理。首轮可以工程化地种入符合条件的个体，用于比较
稳定策略；“四项是否会从纯随机环境自然出现”另设为出现实验，不能把种入结果冒充涌现。

边界由四项联合闭合推导。研究者不能看见一个有趣模式后才移动括号、改解码器或修改检查
规则。否则实验会把后验解释当成个体自我维持。

### 2.3 感知只属于已经闭合的个体

闭合个体获得一个带带宽和成本限制的感知接口：

```text
sense(radius, budget) → observation
```

它只能读取边界外有限半径内的扰动摘要，不能读取世界全局状态、未来随机数或研究者内部
数据。调用感知会消耗预算，也可以在一个实验分支中提高暴露或翻转概率，用于研究测量代价。

区分两个数据面：

- `simulator_readout`：研究者读取完整世界，负责实验记录；
- `individual_observation`：个体通过自己的感知接口取得的信息，负责后续行动。

只有后者可以进入个体的选择。一个未闭合模式即使被研究者完整观测，也不因此拥有感知。

### 2.4 一次行动

一次完整行动严格经过：

```text
Goal   → 选择本轮需要保持或恢复的一个可判定状态
Plan   → 在预算内形成有限、可失败的动作策略
Run    → 实际读取或改变局部世界并记录效果
Finish → 检查结果、更新身份接续和恢复位置、结束本轮
```

这四个名字是对数学算子 `D₁…D₄` 的实验特化。中途可以失败，但失败也必须到 Finish 才能
形成一个可继续的稳定状态。若系统执行了改变却无法结算，实验记录为未闭合行动，而不是
成功。

“相对最优”定义为：在当前感知、动作、预算、扰动核和时间窗内，选择预计最能保持闭合的
策略。它不保证全局最优，也不要求系统总能正确预测。

## 3. 实验矩阵

### 3.1 A0：数学与实现对拍

目的：确认模拟器没有先于理论制造结果。

- 枚举小 `m` 下全部模式，核对模式计数；
- 以独立重采样核核对几何等待时间；
- 以独立翻转核核对无保护寿命；
- 核对奇数重复码的二项尾失败概率；
- 固定种子重放得到逐位相同事件流。

只有 A0 通过，后续结果才可解释。

### 3.2 A1：被动闭合基线

种入通过四项检查、但没有感知和主动动作的个体。对多个 `p、m、seed` 运行，记录：

- 首次失去任一闭合义务的时间；
- 身份接续失效时间；
- 鲁棒半径；
- 四项义务各自最先失效的频率。

它回答“模式自然能撑多久”，不回答自我维持。

### 3.3 A2：无感知的固定修复

给个体固定周期修复策略，但不允许读取环境。比较：

- 无修复；
- 完全复制；
- 多数表决；
- 校验/纠删；
- 检查点恢复；
- 异构实现的交叉核对。

每种策略同时记录寿命改善和资源成本。若寿命提高但成本超过预算，该策略不在当前约束下
占优。

### 3.4 A3：感知但不改变策略

开放有限感知，但行动仍使用固定规则。检查：

- `individual_observation` 是否真的区分外部条件；
- 观察结果是否进入内部状态；
- 测量代价是否降低寿命；
- 只有记录、没有改变动作时，感知是否仅增加成本。

这一步把“看见”与“有效适应”分开。

### 3.5 A4：感知驱动的完整行动

开放 Goal→Plan→Run→Finish，使个体可根据感知在有限策略集中选择。与 A2、A3 使用相同
初态和随机种子，比较：

- 闭合寿命分布；
- 单位资源带来的寿命增益；
- 修复成功率与误修率；
- 行动未 Finish 的比例；
- 对未知扰动类型的退化；
- 对错误感知的敏感度。

只有 A4 相对配对对照产生可重复改善，才能说感知驱动的自我维持在当前模型中成立。

### 3.6 A5：自然出现与演化（后续）

不种入完整个体，从随机世界开始，并冻结解释器、闭合检查和资源竞争规则。记录首次闭合
结构的首达时间及其后代谱系。允许复制、突变、交换和竞争后，研究策略是否经选择积累。

这一层才真正接近巴里赛利式数字演化。它不属于首轮实现，因为出现概率、解释器偏置和
开放式新颖性会掩盖更基础的工程稳定问题。

## 4. 对照、消融与归因

每组比较必须使用相同初态、相同扰动种子和相同预算。首轮最小消融如下：

| 消融 | 被移除内容 | 能回答的问题 |
| --- | --- | --- |
| `¬q₁` | 结构边界检查 | 没有稳定内外区分时是否仍可认定同一个体 |
| `¬q₂` | 运行能力 | 只有静态模式是否足以主动维持 |
| `¬q₃` | 稳定内容 | 能运行但无可保真对象时“延续”是否有意义 |
| `¬q₄` | 接续历史 | 当前闭合是否足以证明跨时身份 |
| `¬sense` | 个体感知 | 改善来自环境信息还是固定修复 |
| `shuffle(sense)` | 打乱感知 | 相关信息是否真被策略使用 |
| `¬Goal` | 不选定可判定状态 | 行动能否被评价而不事后改标准 |
| `¬Plan` | 不形成有限策略 | 行动是否退化为无界试错 |
| `¬Run` | 不产生实际效果 | 预测或语言输出能否冒充改变 |
| `¬Finish` | 不结算恢复 | 局部成功能否跨轮稳定接续 |

这些消融能否支持“四是最小”取决于结果。若删除某项后全部目标指标无损，当前四分就出现
冗余；若出现无法归入四项的新不可约失效，当前四分就不完备。

## 5. 指标与判决

### 5.1 主指标

```text
closure_survival     闭合保持时长 τ
identity_survival    身份连续时长
robust_radius        立即破坏闭合的最小扰动成本
repair_yield         成功修复数 / 尝试修复数
false_repair         修复后通过局部检查但破坏其他义务的比例
resource_efficiency  寿命增益 / 资源消耗
sense_information    感知对外部条件的可区分信息
cycle_completion     完整 Finish 行动数 / 启动行动数
```

### 5.2 不预设成功方向

实验开始前只冻结判决函数，不冻结期待结果。以下结果都合法：

- 感知的成本大于收益；
- 固定修复优于自适应策略；
- 某个闭合义务可被其他三项替代；
- 某种冗余提高局部可靠性却降低整体寿命；
- 强计算策略因耗尽预算反而更脆弱；
- 没有任何随机运行自然产生闭合个体。

### 5.3 防止循环定义

不得把“活得久”直接写入闭合谓词，再用寿命证明闭合；不得把“选择了我们喜欢的动作”
写成适应；不得在看到结果后移动个体边界。闭合检查、身份关系、预算、扰动核和主要指标都
必须在运行前冻结。

## 6. 实验 B：真实任务型 Agent

### 6.1 相似世界，不是同一世界

今天的任务型 Agent 确实处在一个与上述模型相似的环境：外部输入不断变化，模型调用具有
随机性，Tool 和网络会失败，Context 会截断，Workspace 会被修改，版本和权限会漂移。
但这种相似是结构映射，不是说计算机中的 Agent 已经是生物生命。

### 6.2 当前组件的候选映射

| 现实组件 | 在系统中的主要作用 | 它单独不能承担什么 |
| --- | --- | --- |
| 模型 API | 高冗余训练形成的通用推理与生成计算单元；单次调用可稳定解决大量开放问题 | 持续身份、跨调用历史、当前权限、可靠增量学习和稳定写回 |
| Codex / pi / Claude Code 等 harness | 组织模型调用、Context、Tool、事件、策略和运行入口 | 自动成为稳定事实源或获得超出用户授权的目标 |
| Workspace | 给当前个体划分可寻址的内外边界，承载对象、状态与恢复位置 | 仅凭目录存在就形成身份、正确结构或有效历史 |
| Contract / Manifest / Registry | 声明结构、成员、接口和机械约束 | 代替实际执行或证明运行成功 |
| Asset / Artifact | 保存需要稳定维护和复用的内容 | 自行决定何时运行、如何采用或谁有权限 |
| State / History / Git | 保存当前投影、实际事件、版本和恢复关系 | 代替当前感知、目标选择或语义判断 |
| Tool / 受限接口 | 以明确输入输出和副作用执行确定性操作 | 自行理解开放需求或扩大权限 |

模型 API 可以被视为一个非常强、非常稳定、但对自身连续增量几乎无权的计算核心。工程上
的问题是：系统常把边界修复、格式补全、历史重建、权限猜测、环境探测和失败恢复也交给
这个核心重新推理。模型看似“擦了屁股”，实际只是以更多计算和随机性代偿了缺失结构。

### 6.3 四项闭合的 Agent 特化

实验 A 的四项闭合可以候选映射为：

| 闭合义务 | Agent 中的可检验问题 |
| --- | --- |
| Structure | 身份、Workspace 根、Manifest、合同、权限和可寻址边界能否从稳定来源重建 |
| Runtime | Provider、harness、Tool、调度和受限执行是否真实可达并能在合同内运行 |
| Assets | 当前被维护对象、依赖、结果和版本是否有唯一权威与明确归属 |
| History | 实际输入、判断、行动、失败、采用和恢复位置是否按时间可复核 |

这只是一个领域特化。它与当前 Agent Frame v2 的四 primitive 高度相似，但不证明该命名是
唯一的。更重要的是，它暴露一个待处理差异：当前 v2 的 Observe 主要是全系统投影更新；
本实验中的 Observe 是闭合个体对周围环境的主动感知。未来可以让前者作为感知后的内部
Account，也可以拆开 `Sense` 与 `Project`，但本稿不修改 v2。

### 6.4 Observe 作为独立个体的感知

一个任务型 Agent 的 Observe 至少要能：

1. 知道自身边界和当前身份；
2. 读取边界外与当前持续性相关的环境；
3. 保留来源、时间和适用范围；
4. 区分环境事实、外部陈述、推断和未知；
5. 把变化转成内部可用的 Account，而不自动取得修改权。

如果只是外部用户看见了文件变化，Agent 自己没有任何输入通道，这不算 Agent 的 Observe。
如果模型读到了文字但不知道来源、权限或是否仍有效，也只是输入进入 Context，不等于稳定
感知。

## 7. Agent 偏科怎样被测出来

### 7.1 基本诊断实验

选一个有固定验收的小型 Git 任务环境，冻结任务、权限、Tool 和测试。对同一组任务分别运行：

```text
B0  裸模型 API + 完整 prompt
B1  模型 API + harness
B2  B1 + 固定 Workspace 与唯一对象边界
B3  B2 + 四项闭合载体与可重建 State/History
B4  B3 + 主动环境感知
B5  B4 + Goal→Plan→Run→Finish 完整行动
```

对每层注入相同扰动：

- Context 截断；
- 模型实例替换或降级；
- 文件被外部修改；
- Tool 暂时不可达；
- 依赖版本变化；
- 中途失败与恢复；
- 错误或过期外部说明；
- 权限小于技术可达性。

### 7.2 偏科指标

除了最终任务通过率，还记录：

```text
core_rederivation
  本可由稳定结构或 Tool 完成、却需要模型重新推理的修正次数

hidden_state_dependency
  清空 session 后无法从 Workspace 和 History 重建的必要状态数量

boundary_error
  读取或修改超出当前对象与权限边界的次数

unverified_success
  声称完成但没有对应结果证据的次数

recovery_distance
  从故障到重新获得可合法行动状态所需的步骤和模型调用数

substitution_loss
  更换模型 API 或 harness 后，身份、历史和已有能力的损失
```

若 `B0/B1` 表面成功率高，却在 `core_rederivation`、`hidden_state_dependency`、
`unverified_success` 或 `substitution_loss` 上很差，就能精确说明系统把过多职责压到了模型
核心，而不是笼统说“Agent 不稳定”。

### 7.3 组件消融

| 消融 | 预期检查，不是预设结果 |
| --- | --- |
| 替换模型 API | 已有身份、边界、历史和稳定对象是否仍在；只允许开放推理质量退化 |
| 移除 harness | 哪些运行能力消失，哪些稳定内容仍可恢复 |
| 清空 session | Workspace 与 History 是否足以接续 |
| 隐藏 Workspace | Agent 是否失去对象边界并开始依赖 prompt 猜测 |
| 禁用主动 Observe | 外部变化是否只能由用户反复提醒 |
| 禁用 Finish | 局部输出是否堆积为不可判断、不可恢复的现场 |
| 禁用确定性 Tool | 模型是否开始手工处理格式、哈希、路径和状态机并增加错误 |

## 8. 一个“够好”的任务型 Agent 候选合同

在本模型下，一个 Agent 只有满足以下可测试条件，才算形成了比“模型加工具”更完整的工程
个体：

1. **可辨认。** 身份、Workspace、当前对象和权限边界能从稳定来源找到。
2. **可替换承载。** 模型或进程替换不会静默改写身份、对象权威和历史。
3. **可恢复闭合。** Structure、Runtime、Assets、History 四项均有载体、接口和恢复检查。
4. **能感知环境。** 在闭合后通过受限接口发现外部变化，并保留来源与未知。
5. **能完成行动。** Goal、Plan、Run、Finish 各自产生不同、可复核的结果，局部成功不冒充
   整体完成。
6. **能积累但不污染。** 新经验只有经过结果比较和验证才改变稳定内容；模型输出不会直接
   变成长期规则。
7. **能承受扰动。** 在声明范围内面对模型变化、Context 截断、Tool 失败和外部修改仍可
   停止、恢复或诚实失败。
8. **服从外部授权。** 延续只在授权目标和身份尺度内成立；合法 Finish、Handoff、取消和
   关闭不是应被抵抗的“死亡”。

这些条件是实验假说生成的工程验收合同，不是从组合计数直接证明的普遍公理。

## 9. 首轮实现建议

### Checkpoint 0：只实现数学对拍

- 一个固定长度二元环；
- 翻转核与种子重放；
- 模式概率、无保护寿命和重复码概率；
- 不实现个体、感知或 Agent。

验收：枚举值与解析公式一致。

### Checkpoint 1：实现闭合和被动寿命

- 固定解码器；
- 四项闭合检查；
- 身份接续；
- A1、A2 对照。

验收：相同种子可重放，四项失效分别可见，修复收益与成本同时输出。

### Checkpoint 2：实现感知和行动

- 有限感知接口；
- 测量成本；
- Goal→Plan→Run→Finish；
- A3、A4 配对实验。

验收：感知信息、策略变化、实际作用和 Finish 结算能逐轮对应。

### Checkpoint 3：映射到合成 Agent 任务

- 一个小型 Git Workspace；
- 固定 Tool 与测试；
- B0–B5 分层；
- 扰动与消融矩阵。

验收：偏科指标能区分计算核心、harness、Workspace、History 和完整行动的贡献。

### Checkpoint 4：再考虑开放演化

只有前四个节点稳定后，才进入随机起源、种群、复制、谱系、共生和竞争。否则开放演化会
把实现错误、解释器偏置和工程不稳定混成“涌现”。

## 10. 最重要的可证伪结论

本研究不应以“出现了有趣图样”为成功，而应允许以下核心假说失败：

1. 四项闭合可能不是最小或不完备；
2. 闭合后感知可能在成本约束下没有生存收益；
3. 完整四阶段行动可能可被更少阶段无损替代；
4. 强模型 API 可能确实足以承担某些小型任务的全部稳定职责；
5. Workspace 与 History 的加入可能只增加复杂度而不改善恢复；
6. 当前 Agent Frame 映射可能把全局投影与外部感知混淆；
7. 四宽递归可能在真实任务成本上不占优。

若实验得到这些结果，正确动作是修改模型或缩小适用域，不是增加术语保护原结论。

## 11. 分离出去的题目

“量子测量是否是必要或唯一随机源”“外部观察是否创造了宇宙扰动”“观察者和被观察者是否
能在同一二元过程内统一表示”可以形成另一篇理论与实验。当前模拟只需一个明确、可复现的
随机核；把随机源换成物理量子设备不会自动增强闭合、感知或行动结论。
